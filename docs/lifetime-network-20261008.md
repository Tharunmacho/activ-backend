# Lifetime Membership and ACTIV Network release

The website and Android 1.0.3 (version code 4) accompany this backend release.

- The public plan catalogue now returns `price`, `membershipType` and `features` alongside the existing `amount`, `memberType` and `entitlements`. Amounts exposed to clients are rupees; the database continues to store paise. Lifetime Membership is currently configured at INR 200,000. Clients must never convert a missing price into zero or substitute a business-band offer for the held plan.
- Legacy `platinum` keys, routes and historical order identifiers remain compatible. Member, admin, receipt and notification display names use Lifetime Membership.
- Company publication is derived from active membership and payment entitlement. The old company `pending` field did not have a company approval workflow. Owner APIs now return `publication` with the real publishing state and a display status; no approval is fabricated.
- An active Lifetime Membership tier can publish multiple companies. Other active plans include one company. Additional company records can remain as drafts. Publishing an additional company requires the current price of the member's held plan, resolved from paid membership history on the server.
- An additional company payment is stored as `orderType: company_listing` with its `companyId`. An annual payment covers that company for one year from confirmation; a lifetime term does not expire. The owner's personal membership must remain active. These orders never rewrite personal membership payment facts, renewal dates, or membership certificates. Missing plan history requires office reconciliation, rather than guessing a price.
- Existing company records are retained. For standard members with multiple legacy listing flags, the oldest unfunded company uses the included listing; independently paid companies remain eligible. Discovery, product searches, member profiles, trust lists and public share endpoints use the same selection. Concurrent publishing cannot expose more unpaid listings than the entitlement.
- Settings provides the price and term before opening checkout. Existing signed verification, gateway webhook, return verification and reconciliation handle company payments. Mock payments remain disabled in production.
- `/network/companies/:id` exposes the public company whitelist. PAN, GST registration numbers, turnover, ITR and scheme details stay private. `/share/companies/:id` provides crawler metadata and a 1200x630 JPEG with the company's banner, logo and contact details. Withdrawn listings return 404, including their preview images.
- Mobile OAuth returns have an HTML fallback with an explicit Open ACTIV Android intent. Signed expired mobile states may select the error destination only; expiry and cookie checks still gate authentication. Handoff codes expire after five minutes and remain single-use.

Validation: isolated company payment and publication fixtures, public company and social-preview HTTP tests, OAuth provider and replay tests, existing membership upgrade/office document tests, website browser tests, and native TypeScript/Jest checks. No real charge or live customer notification was used for these checks.

Deployment: deploy backend and website commits together, including the website's share-preview rewrite rules. Install the new Android build to receive native certificate/PDF, gold card, pricing and network-label updates. A Git push alone does not update installed Android apps. A fresh Facebook login on the user's device remains the final check of their provider/browser consent path.
